# Spiral Study System — 다회독 적응형 시험 학습 시스템

> **상태:** v1.0 (2026-10-25) · **용도:** 강의 PDF, 수학 문제, 실습 노트북, 기술서적을 대화형 AI와 여러 세션에 걸쳐 공부하는 재사용 가능한 학습 설계.

## 핵심 계약

**회독(pass)은 응답 횟수나 PDF 개수가 아니라 `설명의 깊이`를 뜻한다.** 하나의 회독은 수십 번의 대화로 이루어질 수 있고, 하나의 PDF도 여러 학습 묶음(chunk)으로 나눌 수 있다. 전체 범위의 개념 지도를 매 회독 다시 통과하되, 다음 회독에는 기존 지도에 더 정밀한 지식을 추가한다.

- **넓게 → 깊게:** 전체 범위의 상위 구조를 파악한 후 동일한 지도를 점차 확장한다.
- **실제 이해:** 1회독에서도 개념의 뜻·목적·작은 예시는 반드시 설명한다. **단어 목록은 학습 완료가 아니다.**
- **일관된 깊이:** 한 회독의 각 영역에 같은 설명 수준을 적용하되, 지식 유형(개념·수식·알고리즘·코드)에 맞는 활동을 선택한다.
- **학습 → 인출 → 피드백:** 묶음 단위 소규모 질문, PDF/단원 단위 종합 질문, 회독 종료 전 범위 평가를 사용한다.
- **근거와 완전성:** 모든 개념·문항에 원본 자료 위치를 붙인다. 아직 열어보지 않은 원본·이미지·코드·시험 제외 범위는 추측하지 않는다.
- **상태 보존:** 다음 대화에서는 이전 내용을 기억한다고 가정하지 않고 기록 파일로 재개한다.

## 5분 시작 가이드

1. 원본 자료(PDF, ipynb, 교재)와 시험 범위·시험 방식(알려진 만큼만)을 제공한다.
2. 에이전트에 `spiral-study-coach` 스킬을 사용하여 **원본별 개념 목록·출처·자료 유형**과 1회독 지도를 만들게 한다.
3. 1회독은 과목 전체의 구조적 의미를 다루되, **몇 개의 작은 묶음씩** 설명하고 문제를 푼다. 한 메시지에 모든 PDF를 요약하지 않는다.
4. 답변 후 원인별 피드백을 제공하고 상태 기록을 업데이트한다.
5. 모든 예정 묶음의 1회독 설명·테스트가 끝나면 전 범위 누적 평가를 거쳐 2회독으로 전환한다.
6. 다음 채팅에서는 상태 파일+원본 접근 여부를 확인하고 `next_unit_id`부터 이어간다.

## 기본 깊이 사다리 (고정 규칙이 아니라 출발점)

| 회독 | 질문 | 최소 설명 | 평가 |
|---|---|---|---|
| P1 전체 구조 | 무엇/왜? | 정의, 목적, 쉬운 예시, 상위·인접 관계 | 구분·설명·예시 판단 |
| P2 원리 | 어떻게/언제? | 작동 메커니즘, 비교, 실패 사례 | 상황 적용·개념 비교 |
| P3 수학/절차 | 왜 이 식·순서? | 수식 해석·유도, 단계 계산, 데이터 흐름 | 계산·단계 결과 예측 |
| P4 세부/구현 | 실제로 구현하면? | 예외, 조건, 코드/텐서, 디버깅 | 빈칸·실행 추적·오류 수정 |
| P5+ 통합 | 단서를 섞어도 풀까? | 총정리, 오개념 대조, 빈틈 보강 | 전 범위 모의고사·지연 재인출 |

> 특정 PDF에 코드가 없다면 P4는 사소한 코드 암기가 아니라 그 과목의 실제 세부 규칙·사례·예외로 대체한다. 어려운 P1 수학 개념도 뜻·목적·예시를 충분히 설명한다.

## 새 대화에서 재개하기 위한 예시 요청

> 첨부한 원본 및 학습 상태 JSON을 바탕으로 spiral-study-coach 규칙을 적용해 공부를 재개해줘. 현재 `pass`, `next_unit_id`, 미해결 질문, 이전 오답과 출처 확인 상태를 먼저 검증해. 기존 회독의 학습 깊이를 유지하고, 이번에는 한 학습 묶음만 설명한 뒤 관련 문제를 내줘. 답은 내가 제출하기 전까지 공개하지 마.

## 자료 관리와 주의

- **시스템 설계 문서는 공개 가능한 일반 규칙**으로 작성했다. 강의 원본 PDF, 과제 풀이, 개인정보와 원본 저작물 전체를 이 저장소에 업로드하지 않는다.
- 각 과목별 진행 데이터는 별도 로컬/개인 저장소에 보관하고 파일명·해시·페이지/셀 번호를 기록한다.
- 이 폴더는 학습 방법/실행 계약이며, 특정 챗봇에서 자동으로 Skill이 설치되거나 대화 상태가 무조건 공유된다는 의미가 아니다.
- 자세한 판단 근거는 [DESIGN.md](DESIGN.md), 연구 결과와 제한은 [RESEARCH.md](RESEARCH.md), 실제 운영법은 [PROTOCOL.md](PROTOCOL.md), 품질검수는 [VALIDATION.md](VALIDATION.md)를 참고.
