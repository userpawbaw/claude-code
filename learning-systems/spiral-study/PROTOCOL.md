# 운영 프로토콜 — 원본 입력부터 다음 회독까지

이 문서는 AI 튜터 또는 사람이 따라 할 수 있는 **실행 절차**다. 동일 자료를 한 번에 모두 요약하는 방식은 금지한다.

## A. 시작: 수업 자료를 인수한다

1. **범위 계약:** 사용자가 제공한 원본의 명칭·버전·파일 개수·시험 범위·제외 범위·시험 방식·남은 시간을 기록한다. 모르는 것은 `unknown`.
2. **실제 확인:** PDF는 페이지 내용(텍스트 + 중요한 이미지/도표)을 검토하고, ipynb는 `cells`의 코드/markdown/출력 중 시험 관련 부분을 확인한다. 단순 파일명·검색 스니펫으로 전체 파악했다고 주장하지 않는다.
3. **자료 색인:** `source_id`, 파일명, 원본 페이지(1-base), 노트북 셀 인덱스(0-base)와 필요시 셀 원문 첫 줄을 기록한다. 시각자료가 포함되면 `visual_review_required` 표시.
4. **범위표:** `unit_id` 단위로 `topic→subtopic→concept`을 만든다. 모든 항목에 근거를 연결하고 미확인/시험 제외를 구분한다. 전체 훑기가 불가능할 땐 확인 범위만 기록하고 이후 보강.
5. **지식 그래프:** `prerequisite`, `related`, `confusable_with`, `math_to_code` 연결을 붙인다. PDF 순서와 개념 순서는 별개일 수 있다.
6. **학습 계획:** 기존 지식·시험 형태를 반영해 P1 지도와 학습 단위를 분할한다. 시험에 코드가 포함되면 ipynb를 범위표에 독립 소스로 등록한다.

**원본/외부지식 구별:** 사용자 자료의 내용은 `[SOURCE]`, 외부 보충은 `[ENRICHMENT]`, 불확실한 해석은 `[INFERENCE]`로 내부 관리한다. 원본과 모순되면 원본 표현을 숨겨 교정하지 않고 '원본 표현 / 보충 설명 / 불일치'를 설명한다.

## B. 진행: 학습 단위(chunk)를 가르친다

**한 채팅=한 회독이 아니다.** 한 PDF도 여러 채팅으로 나눌 수 있다. 새로운 응답이 생성됐다고 자동으로 다음 unit/pass로 옮기지 않는다.

매 학습 응답은 아래 계약을 지킨다.

1. `현재 Pn / source / unit / 이 단위에서 다룰 개념`을 짧게 표시한다.
2. 이전 학습에서 필요한 선행 지식만 **인출 질문 한두 개**로 이어간다(진도/사용자 선호에 맞춰 조정).
3. **현재 회독의 목표 깊이**로 설명: P1도 **정의 + 필요한 이유 + 간단한 예 + 상위 관계**는 반드시 포함.
4. 관련 표, 수식, 코드, 이미지에 원본 출처 위치를 밝힌다. 수식에는 각 기호 의미 및 가정을 덧붙인다.
5. 종속된 몇 개 개념까지만 다룬 뒤 멈춘다. 양이 많으면 다음 메시지에 같은 깊이로 이어간다.
6. 학습 묶음의 설명이 완료되면 작은 테스트를 제공한다. 대답을 기다리는 단계에서 정답·해설을 공개하지 않는다(사용자가 요청하면 예외).
7. 답변을 받으면 문항별 정오답 + 확신도 + 이유 오류 태그를 적고, 핵심 반례/정정 설명 후 재인출 항목을 예약한다.
8. 학습한 unit, 문항/성취 기록, `next_unit_id`, 미해결 질문을 상태 파일에 반영한다. 실제 영속 기록을 쓸 수 없다면 **복사 가능한 상태 델타**를 제공한다.

### 최소 설명 기준: P1에도 단어 나열 금지

나쁜 예: 'MLE: 최대우도추정. MAP: 최대사후추정. PCA: 차원축소.'

좋은 예: 'MLE는 관찰한 데이터가 지금의 모수값에서 나타나기 얼마나 그럴듯한지 평가하고, 가장 큰 값을 주는 모수를 고른다. 동전을 10번 던져 앞면이 7번이라면 앞면 확률을 데이터로 추정한다. MAP는 같은 데이터를 보면서 모수에 대해 미리 알고 있던 정보를 추가 반영한다. 둘은 W2 확률/통계 추론의 하위 개념이다.' (정확한 수치 계산은 P2/3로 확장 가능)

**질문-수준 규칙:** P1에서는 계산할 수 없어도 '왜 그런 목표를 갖는가'를 설명할 수 있어야 한다. P3에서 유도할 수 없다면 P3 완료로 표기하지 않는다.

## C. 세 유형의 평가 게이트

| 지점 | 평가 범위 | 목적 | 완료 조건 |
|---|---|---|---|
| chunk 종료 | 직전에 학습한 1~수개 개념 | 이해 직후 인출 | 답 제출·오개념 피드백·로그 |
| PDF/단원 종료 | 이전 unit까지 연결 | 국소 누락 및 개념 관계 | 예정 unit 출처 확인 + 단원 평가 |
| pass 종료 | **전체 시험 범위** | 균일한 깊이·복합 연결 검사 | 모든 포함 unit에서 해당 깊이 수업 및 평가, 미확인 범위 별도 고지 |

**점수로만 이동하지 않는다.** 목표 점수(예: 80%)는 사용자와 조정할 수 있는 운영 휴리스틱일 뿐 절대 기준이 아니다. 통과와 별개로 낮은 확신의 정답, 높은 확신의 오답, 출처 불확실 항목은 복습 큐에 남긴다.

원본 전체를 아직 색인하지 않았다면 `full_pass_complete=false`로 유지한다. 시간 부족으로 압축 모드가 필요하면 빠진 범위를 명시한 `exam-cram partial coverage`로 표시하며 정상 완료와 혼동하지 않는다.

## D. 깊이 사다리: 영역 전체가 동일한 단계

- **P1 / 개념틀:** 배경, 문제, 정의, 목적, 쉬운 예, 지도상 위치. 수학 증명/세세한 API 옵션은 강요하지 않는다.
- **P2 / 원리:** 단계적 메커니즘, 필요한 전제, 헷갈리는 개념 비교, 간단한 반례.
- **P3 / 수식과 계산:** 주요 식을 원본 표기로 해석하고 유도, 계산; 알고리즘 상태 변화를 표로 추적. 실제 자료가 수학 없는 분야면 동등한 세부 작동 원리로.
- **P4 / 세부와 구현:** 경계 조건, 오류 진단, 코드 tracing→completion→debugging→generation, shape/dtype/device 등 원본 범위의 함정.
- **P5+ / 전범위 통합:** 용어·원리·수식·코드를 섞은 새로운 문제와 지연 인출. 강점은 짧게, 취약점은 깊게.

특정 유닛만 앞 단계가 아니라 뒤 단계를 선행 학습해야 이해되는 경우, **국소 보충(aside)**임을 명시하고 회독 전체의 단계는 올리지 않는다.

## E. 문제은행 운영 규칙

각 문항의 최소 메타데이터:

`item_id, unit_ids, pass, cognitive_target, difficulty, format, stem, options?(객관식), answer_key(hidden), rationale, source_refs, distractor_rationales, status`.

- 첫 공개 시 정답을 숨긴다. 사용자의 실제 답변 후에만 해설·정답 공개.
- 보기 4개가 모두 동등한 문장 범주에 속하는지, 정답이 하나인지 확인; 다답 가능하면 다답형이라고 명시.
- 정답은 원본으로 검증하거나, 독립적으로 유도/실행 가능해야 한다. **출처가 불완전하면 문항 대신 보류한다.**
- 서로 다른 문항 번호라도 같은 지식만 반복하면 **범위 커버리지 증가로 계산하지 않는다.**
- `recall`, `compare`, `apply`, `derive`, `trace`, `debug` 사고 유형을 표시한다.
- 순수 암기 문제와 개념 적용 문제의 구성을 점차 전환; P1은 단원 구분, P2+는 선행 학습 후 유사 문제 혼합.
- 수학 문항은 가정·표기·손실 정규화 계수를 명시; 코드 문항은 프레임워크 버전, 입력 크기, dtype/shape 필요 정보를 명시.

## F. 오답 분류와 다음 행동

| 태그 | 관측 | 다음 행동 |
|---|---|---|
| `recall` | 정의/공식을 기억 못함 | 짧은 핵심 단서 + 시간차 재인출 |
| `concept` | 정의·원리 자체를 오해 | 다른 비유/반례로 재설명 + 설명 요구 |
| `discrimination` | 비슷한 개념 혼동 | A vs B 표, 혼합 문항 |
| `application` | 알지만 새로운 상황에 적용 실패 | 예제 1회 후 유사 문제 독립 풀이 |
| `math` | 미분/대수/확률 전개 오류 | 중간 단계 역추적, 부분 계산 |
| `code` | shape/API/연산순서/버그 | tracing→부분 코드→수정 |
| `careless` | 근거는 맞고 산술/표기 실수 | 체크리스트, 재검산 |
| `source_gap` | 자료 미검증/문항 모호 | 정답 판정 보류, 원본 재확인 |

`confidence=low`인 정답도 재인출 대상으로 유지. 반복 평가 때는 숫자·문장만 바꾼 사실상 동일 문항 대신 **동일 개념의 새 문항** 사용.

## G. 간격 복습 및 일정

학습 중후반에 예전 개념을 다시 질문한다. 여유가 있으면 다음날/며칠 뒤/일주일 뒤 같은 간격을 초기값으로 쓰되 **근거에 의해 고정된 유일한 최적 일수라고 주장하지 않는다.** 오답·낮은 확신은 더 이른 재확인, 확실한 반복 정답은 더 늦은 재확인을 고려한다. 예약 도구를 실제 호출하지 않았다면 알림이 설정됐다고 말하지 않는다.

## H. 중단/재개 프로토콜

**학습 시작 시:** 원본의 접근 상태, 동일 문서 버전, `pass`, `next_unit_id`, `open_questions`, `unresolved_misconceptions`을 확인.

**학습 종료 시:** 1) 완료한 unit·범위, 2) 맞고 틀린 이유, 3) 새로 확인한 원본 위치, 4) 남은 영역, 5) 다음 unit, 6) 복습 큐 및 미해결 질문을 **직렬화 가능한 상태**로 남긴다. 링크만 있다고 내용을 열 수 있는지는 별도 확인.

**충돌 시:** 파일 원본 우선 → 가장 최근 사용자 확인 상태 → 자동 추론 상태 순으로 신뢰한다. 원본 변경(파일 해시/페이지 구조 등) 시 색인·문항을 재검증한다.
