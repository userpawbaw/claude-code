# 설계 의도 · 대안 평가 · 선택 이유

## 1. 문제 정의

대량의 강의 PDF와 프로그래밍 노트북을 시험에 대비해 공부할 때, AI가 한 응답에 모든 파일을 압축 요약하면 다음 문제가 발생한다.

1. **명칭만 나열**하고 실제 개념·용도·예시를 설명하지 않는다.
2. 페이지 수가 많을수록 누락이 생기고, 섹션마다 깊이가 들쭉날쭉해진다.
3. 문제는 내지만 원본의 어떤 부분을 평가하는지 추적하지 않는다.
4. 수식과 실습 코드를 별개로 암기해 전이가 어렵다.
5. 채팅이 바뀌면 완료 범위와 오답/미해결 항목을 잃는다.
6. 기초 회독을 끝내기도 전에 일부 주제만 과도하게 깊게 들어간다.

**성공의 기준은 '짧은 요약 완성'이 아니라, 전체 범위 누락을 통제하며 시간차 인출과 적용력을 개선하는 것**이다.

## 2. 무엇을 최우선시하나

| 우선순위 | 원칙 | 확인 질문 |
|---|---|---|
| 1 | 원본 충실성·누락 통제 | 어느 PDF 페이지/노트북 셀에 근거하는가? 미확인 영역이 남았는가? |
| 2 | 회독 깊이의 균일성 | 같은 P1인데 어떤 단원은 명사만, 어떤 단원은 증명까지 다루지 않았는가? |
| 3 | 설명의 최소 완결성 | 초심자도 정의·목적·예시를 말할 수 있는가? |
| 4 | 기억 인출과 피드백 | 답을 보지 않고 설명했는가? 틀린 원인을 구분했는가? |
| 5 | 관계 중심 지식 구조 | 새 사실을 기존 개념 지도에 붙일 수 있는가? |
| 6 | 유형별 학습 도구 | 정의/수식/알고리즘/코드에 다른 연습을 썼는가? |
| 7 | 여러 채팅 간 재현성 | 원본과 상태 파일만으로 다음 사람이 같은 단계에서 시작할 수 있는가? |

## 3. 핵심 구성

### 3.1 Spiral passes + nested chunks

- 매 회독에서 **전체 시험 범위**를 한 번 통과한다(완료는 범위 매트릭스 기준).
- 실제 진행은 **하나의 개념 묶음씩**, 필요한 만큼의 여러 응답/세션으로 나눈다.
- PDF 경계와 chunk 경계는 같을 필요 없다. 개념의 선행 조건과 논리적 흐름을 우선한다.
- 한 PDF를 아직 마치지 못했어도 해당 회독을 유지한다. P2로 성급히 승격시키지 않는다.
- 중요도는 설명 분량/연습 횟수에 반영할 수 있지만 '중요하지 않다'는 이유로 원본 개념을 무단 삭제하지 않는다.

이 구조는 사용자의 **완전성·깊이 일정성·다회독** 요구를 충족하는 **운영 설계**다. 'Spiral' 자체가 실험적으로 단일 최적 학습법으로 입증되었다고 주장하지 않는다. 실증 근거는 아래의 개별 학습 활동(인출·간격·혼합·예제 점진 제거)에 둔다.

### 3.2 유형별 설명

| 유형 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|
| 정의·분류 | 뜻, 필요성, 한 예 | 인접 개념과 차이 | 경계/조건/반례 | 지엽적 예외·혼합 판별 |
| 수학·확률 | 변수의 의미, 도입 목적 | 직관·가정·수식 읽기 | 유도·계산·조건 | 복합 문제·증명 오류 |
| 알고리즘 | 입력→처리→출력 그림 | 단계/불변 조건 | 손계산·복잡도(원본에 있으면) | 경계 사례·디버깅 |
| 실습 코드 | 파이프라인과 객체 역할 | 중요한 API·shape 흐름 | 수식↔라인 대응 | trace→빈칸→수정→구현 |

회독이 내려갈수록 P1 내용을 잊어도 된다는 뜻이 아니다. **기존 층을 재인출한 뒤 새 층을 붙인다.**

### 3.3 지식 맵 + 출처 테이블 + 상태 로그

지식맵: 상·하위 개념, 선행 조건, 혼동 관계, 수식/코드 대응을 개념 ID로 유지.

원본 인덱스: source_id, 파일명, 원본 페이지/셀, 확인 상태(verified/unverified), 제외 여부의 근거.

학습 상태: pass, unit별 설명 완료/문제 완료, 문제별 결과·확신도, 오답 유형, 다음 작업 및 미해결 질문을 영속 데이터에 기록.

## 4. 대안 대비 선택 이유

| 접근 | 장점 | 한계 및 채택 판단 |
|---|---|---|
| PDF 통째 압축 요약 | 빠른 길잡이 | 단어 나열·누락·분량 불균형 위험 → **초기 지도**에 한해 사용 |
| PDF를 첫 번째부터 마지막까지 한 번만 정독 | 자료 순서 충실 | 기초를 잊기 쉽고 개념 간 전이 검증이 부족 → **원본 색인**으로 보완 |
| 단원 하나를 완벽히 끝낸 뒤 다음으로 | 국소적인 숙달 | 전체 구조 학습 지연, 초기에 세부 내용 과다 → 회독 단위로 깊이를 조절 |
| 재독·밑줄/예쁜 정리 | 친숙도와 탐색 편의 | 인출 성공을 직접 확인하기 어려움 → **보조 도구**로만 사용 |
| 전체 범위 무작위 문제만 반복 | 시험 대비·개념 선택 연습 | 초보자는 기초 설명 부족, 틀린 이유 모호 → 묶음 학습 후 단계적으로 혼합 |
| 플래시카드만 사용 | 용어·정의 인출에 유리 | 유도/코딩/응용력 평가 불충분 → 기본 용어용 보조 도구 |
| 일정 시간마다 자동 다음 회독 | 진도 관리가 쉬움 | 학습 누락·상태 불일치 → **개념별 완료 게이트**와 함께 사용 |
| 제안 시스템 | 큰 그림+인출+계층적 세분화+출처 추적 | 운영 기록 관리 비용 증가. 자료가 극히 적거나 단기 단순 시험에는 경량화 권장 |

※ 실제 비교 연구의 효능은 해당 학습 활동과 연구 대상 범위에 국한되며, 위 표의 설계 판단 전체가 하나의 RCT로 검증됐다는 뜻은 아니다.

## 5. 근거 강도 및 한계

- **근거 강함:** 단순 재독에 대한 연습시험·간격 두기 유용성(Dunlosky et al. 2013; Donoghue & Hattie 2021), 지연 검사에서 인출 효과(Roediger & Karpicke 2006).
- **상황 의존/중간 수준:** 혼합 연습은 이미 배운 **서로 혼동하기 쉬운 문제 유형**을 구별할 때 도입한다(Rohrer & Taylor 2007; Taylor & Rohrer 2010). 처음부터 모든 초보자 학습을 무작위 섞지 않는다.
- **초보자 지원:** 해결된 예제→부분 해결→독립 해결의 점진적 지원 제거는 초보자 수학/프로그래밍 과제에 타당한 근거가 있다(Renkl & Atkinson 2003; Renkl et al. 2004).
- **설계 가설:** 5회독 사다리의 단계 수, 최소 문항 수, 점수 기준, chunk 길이는 과목/시험/학습자에 맞춘 운영 휴리스틱이며 연구가 특정 숫자를 보장하지 않는다.
- **메타인지 경계:** 한 번 맞혔다고 학습을 종료하지 않고, 자신감이 낮았던 정답도 나중에 재인출한다(Karpicke & Roediger 2008).

연구별 DOI·링크와 조건은 [RESEARCH.md](RESEARCH.md)에 기록.

## 6. 적용 범위 / 적용하지 말 것

적합: 강의 PPT/PDF, 기술책, 계산/개념 혼합 시험, 코드 포함 과제. 시험 방식에 따라 문제 구성을 조정.

주의: 절대적 시험 출제 확률을 추정하거나 강사의 범위 제외 지침을 꾸며내지 말 것. 사용자가 직접 준 원본 내용과 외부 보충 설명은 구분할 것. 챗봇의 기억이 지속된다는 가정 없이 상태 파일을 명시적으로 저장/읽을 것.

## 7. 설계 수용 기준

1. 같은 P1 강의 설명에서 **정의+목적+예시**가 하나도 빠지지 않는다.
2. 원본의 모든 주요 개념이 범위표에서 `verified`, `needs_review`, `excluded_with_evidence` 중 하나다. 미확인 자료는 완료로 세지 않는다.
3. 학습 chunk / PDF / pass 수준 평가가 각각 존재한다.
4. 수식/코드 문제에는 근거 위치와 의도한 사고 유형이 있다.
5. 오답은 원인별로 다음 회독/간격 복습에 환류된다.
6. 임의 채팅 중단 후 상태 파일로 현재 위치를 복원 가능하다.
7. 관련 도구가 없더라도 텍스트 문서와 학습 자체는 계속될 수 있다.
